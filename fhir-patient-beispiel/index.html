FHIR-Patient-Beispiel: JSON lesen und verstehen

Die Patient-Ressource enthält laut Spezifikation demografische und andere administrative Angaben zu einer Person oder einem Tier, das Gesundheitsleistungen oder andere gesundheitsbezogene Dienste erhält. Das Beispiel darunter stammt aus der Spezifikation und enthält bewusst viele Sonderfälle: mehrere Namen, eine Adresse, einen Kontakt und eine Erweiterung an der Geburtsangabe.

Die Daten bleiben in Ihrem Browser: Es wird nichts hochgeladen. Nur zur Ansicht, kein Validator, kein Medizinprodukt.

Beispiel „Patient“: Original in der FHIR-Spezifikation R4, Lizenz CC0 1.0. Unverändert bis auf die Formatierung.

Das Beispiel Feld für Feld

Die Tabelle nennt Elemente des Beispiels. Die Werte stehen so in der Beispieldatei, nicht in einer Beispielrechnung.

ElementWert im BeispielBedeutung
id"example"Logische ID der Ressource. Sie ist Teil der Adresse, unter der ein Server sie bereitstellt: [base]/Patient/[id].
identifier[0].value"12345"Eine Kennung des Patienten. system bestimmt den Namensraum der Nummer, assigner nennt die ausgebende Stelle, type die Art der Kennung (hier der Code MR).
activetrueOb der Datensatz in Gebrauch ist (nach der Spezifikation: „in active use“). Es sagt nichts über den Gesundheitszustand aus.
name[0]{"use":"official","family":"Chalmers","given":["Peter","James"]}Ein HumanName. use unterscheidet hier official, usual und maiden; given ist eine Liste, family ein Text.
name[2].period{"end":"2002"}Der Mädchenname ist nur bis 2002 gültig. Einen Namen mit Gültigkeitszeitraum zu markieren, ist der Zweck von period.
telecom[1]{"system":"phone","value":"(03) 5555 6473","use":"work","rank":1}Ein ContactPoint mit system (phone), use (work) und rank als Rangfolge.
gender"male"Administratives Geschlecht für Verwaltungszwecke. Erlaubt sind male, female, other und unknown.
birthDate"1974-12-25"Ein date: JJJJ, JJJJ-MM oder JJJJ-MM-TT, nicht TT.MM.JJJJ.
_birthDate.extension[0].url"http://hl7.org/fhir/StructureDefinition/patient-birthTime"Der Unterstrich-Name trägt Zusatzangaben eines einfachen Werts. Hier hängt eine Erweiterung (patient-birthTime) die Uhrzeit der Geburt an das Datum.
deceasedBooleanfalseAuswahlelement deceased[x]: Der Name enthält den Datentyp. Hier deceasedBoolean; die Spezifikation nennt als Alternative deceasedDateTime.
address[0].line["534 Erewhon St"]Straße und Hausnummer als Liste von Zeilen; daneben stehen city, state, postalCode und ein Freitext in text.
contact[0].name.family"du Marché"Eine Kontaktperson mit eigenem Namen, Telefon und Adresse (Patient.contact). Der Unterstrichwert _family trägt wieder eine Erweiterung.
managingOrganization.reference"Organization/1"Ein Verweis auf eine andere Ressource. Als einzelne Datei lässt er sich nicht auflösen; in einem Bundle würde der Viewer zum Eintrag springen.

Was die Spezifikation dazu sagt

Die Spezifikation führt Patient als normative Ressource (Maturity Level N). Sie beschreibt, dass ein Patient-Datensatz in der Regel von jeder Einrichtung gepflegt wird, die den Patienten behandelt; wird jemand in mehreren Einrichtungen behandelt, kann es daher mehrere Patient-Ressourcen geben. Nicht alle Konzepte sind in der Basisressource enthalten; die Spezifikation nennt als Beispiele Ethnie, Organspende-Status und Staatsangehörigkeit.

Im Viewer ausprobieren

Ändern Sie das Beispiel im Eingabefeld und klicken Sie auf „Anzeigen“. Beim Erzeugen dieser Seite wurden die folgenden Änderungen mit demselben Code geprüft:

  • Setzen Sie "birthDate": "25.12.1974" statt "1974-12-25". Der Viewer meldet: „birthDate: "25.12.1974" ist kein gültiges FHIR-date (erwartet JJJJ, JJJJ-MM oder JJJJ-MM-TT).“ (Warnung)
  • Schreiben Sie "gender": "männlich". Der Viewer meldet: „Patient.gender: "männlich" steht nicht in der Werteliste (male, female, other, unknown).“ (Warnung)

Mit dem FHIRPath-Tester können Sie Namen und Telefonnummern gezielt auswählen, etwa name.where(use='official').given.first().
