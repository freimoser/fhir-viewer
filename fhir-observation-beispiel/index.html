FHIR-Observation-Beispiel: Messwerte als JSON lesen

Observation ist die Ressource für Messungen und einfache Feststellungen zu einem Patienten oder Gerät, zum Beispiel Vitalwerte wie Körpergewicht und Blutdruck oder Laborwerte. Hier das Körpergewicht; den Blutdruck mit zwei Teilwerten laden Sie über die Schaltfläche „Blutdruck“.

Die Daten bleiben in Ihrem Browser: Es wird nichts hochgeladen. Nur zur Ansicht, kein Validator, kein Medizinprodukt.

Beispiel „Observation (Körpergewicht)“: Original in der FHIR-Spezifikation R4, Lizenz CC0 1.0. Hier ohne SNOMED-CT-Codierungen und ohne Narrativ (text), weil SNOMED CT gesondert lizenziert ist.

Das Beispiel Feld für Feld

Die Tabelle erklärt das Körpergewicht-Beispiel (darunter geladen). Zum Blutdruck-Beispiel gehört der Abschnitt „component“ weiter unten.

ElementWert im BeispielBedeutung
status"final"Pflichtfeld (1..1): Stand des Ergebnisses, hier final.
category[0].coding[0].code"vital-signs"Einordnung der Observation. Im Beispiel vital-signs (Anzeigetext „Vital Signs“).
code.coding[0].code"29463-7"Was gemessen wurde, ausgedrückt als Code aus einem Codesystem Das Beispiel nennt drei Codierungen: zwei aus LOINC (system http://loinc.org) und eine aus einem lokalen System (acme.org). Dasselbe Konzept darf mehrfach codiert sein. Das Element code ist Pflicht (1..1).
subject.reference"Patient/example"Verweis auf den Patienten, zu dem die Messung gehört; encounter verweist entsprechend auf den Kontakt.
effectiveDateTime"2016-03-28"Zeitpunkt der Messung (effective[x]). Bei Datumsangaben ohne Uhrzeit genügt JJJJ-MM-TT.
valueQuantity.value185Der Messwert (value[x]) als Zahl; die Einheit steht daneben.
valueQuantity.unit"lbs"Lesbare Einheit. Daneben steht code mit dem maschinenlesbaren UCUM-Code (system http://unitsofmeasure.org) – hier [lb_av] für Pfund. Das Beispiel ist also in Pfund angegeben; der Viewer rechnet nicht um.

Was die Spezifikation dazu sagt

Observation ist laut Spezifikation eine normative Ressource (Maturity Level N). Die meisten Observations sind einfache Name/Wert-Paare mit Metadaten; manche fassen andere Observations logisch zusammen oder bestehen aus mehreren Komponenten (component). Jede Komponente hat einen eigenen code (1..1) und einen eigenen Wert (value[x]). Beim Blutdruck-Beispiel sind das ein systolischer und ein diastolischer Wert, die nur gemeinsam Sinn ergeben. Der Wert und ein dataAbsentReason (Grund für einen fehlenden Wert) dürfen nicht gleichzeitig vorkommen (Regel obs-6). Ein DiagnosticReport gibt nach der Spezifikation den klinischen oder Workflow-Kontext für eine Gruppe von Observations; er verweist auf sie, um Labor-, Bildgebungs- und andere Daten zu einem vollständigen Bericht zusammenzufügen.

Im Viewer ausprobieren

Ändern Sie das Beispiel im Eingabefeld und klicken Sie auf „Anzeigen“. Beim Erzeugen dieser Seite wurden die folgenden Änderungen mit demselben Code geprüft:

  • Löschen Sie die Zeile "status": "final". Der Viewer meldet: „Pflichtfeld "status" fehlt (in R4 mit Kardinalität 1..1).“ (Warnung)
  • Fügen Sie neben valueQuantity ein zweites Feld "valueString": "185" hinzu. Der Viewer meldet: „Mehrere value[x]-Felder gleichzeitig (valueQuantity, valueString). Es darf nur eines vorkommen.“ (Fehler)

Den Blutdruck lesen Sie im FHIRPath-Tester mit component.value.ofType(Quantity).value; dort steht auch, warum eine naheliegende Variante mit code.coding.code nichts findet.
